# Native Tower and workspace discovery

After sign-in, PIN unlock or restored trusted-device startup, Android makes a bounded attempt to recover the current identity's self-encrypted workspace indexes. Its connection screen lists verified Towers separately. The user selects a Tower, then explicitly enables its accessible workspaces in the existing chooser. A fresh installation starts with an empty enabled-workspace preference; upgrades preserve remembered workspaces, queued work and partition migration. Discovery itself never changes connections or starts a workspace runtime. Manual HTTPS entry and retry remain available. Workspace-list retry captures the current identity's saved Tower connections, independently of any active workspace, so a failed first listing or an all-paused installation can recover. The chooser keeps Towers with no listed rows visible and offers Refresh workspace lists; retrying a pending second Tower does not change the workspace already selected on the first. FIPS locators are rejected without another-transport fallback.

The existing `workspace-self-index` protocol is shared with Deets, Ambulando web and native clients: kind 33356, `flightdeck_workspace_self_index` v1, NIP-44 v2 to self, author/current-user recipient, protocol/version/originating-app/address tags. Relay queries omit `app_pub`. The originating app namespace is separate from the per-workspace locator app identity, which remains the app header for signed Tower membership requests.

The reader verifies event IDs and Schnorr signatures and reduces authentic kind/current-user events by their first NIP-33 `d` address before validating singleton tags, payload and decryption. A newer authentic malformed/unreadable event or tombstone suppresses the older address; duplicate `d` tags suppress only their first address and cannot suppress unrelated Towers. It validates flat and nested locator forms, payload user/app/version, address hash, canonical npubs, UUID, HTTPS origin and future-time bounds. Every admitted candidate requires fresh signed `/me` and matching Tower, workspace, service, owner and locator-app identities. The descriptor must match the candidate Tower. Failures are isolated per candidate. Selecting a Tower uses the existing authenticated complete workspace pagination, including workspaces with no index; loops, missing continuation, incomplete/empty continuation pages and page-count limits fail visibly.

Native originating namespace metadata lives in [app-identity.json](app-identity.json), shared with iOS. It is the first valid even-y secp256k1 x-only point from SHA256 of UTF-8 `org.wingman.nstack.app:studio.otherstuff.ambulando.native:v1:<counter>` starting at zero; counter 1 is the first valid point. No private scalar was created or stored. The unlocked user identity encrypts and signs every event. This namespace never replaces the workspace locator app or authenticates to Tower.

Explicit workspace enable/open triggers automatic announcement only after fresh matching `/me`. Success requires a relay ACK and exact-event readback/signature/decryption. The ciphertext-only outbox keeps the exact signed event under the existing origin/signer/workspace/app boundary and retries it after restart or on the chooser's retry control. Failed publication leaves the verified connection usable. Disabling a workspace or locking cancels publication activity and preserves pending state. Background read credentials cannot encrypt or decrypt; IdentityService uses the unlocked vault internally under its mutex and clears temporary key copies. Locator plaintext is bounded to 65535 UTF-8 bytes; relay/event/count/time budgets also apply.

Core tests use the shared real nostr-tools fixture (foreign app namespace, two Towers, flat/nested locators and tombstone), signed malformed-newest regressions, stale/revoked identity checks, selected-Tower pagination, native namespace derivation, ciphertext retry/readback, locked-vault refusal and persisted explicit-selection boundaries. Existing workspace catalog/runtime/store tests cover the original multiple-Tower data isolation and migration behavior. Live relay publication and in-place device upgrade remain separate release checks.
